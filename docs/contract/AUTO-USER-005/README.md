# Automation test runs (partial)

No real provider call or consent was used. The existing automation editor has a test panel for a saved definition; save a disabled draft, choose a real readable record and a simulated created/updated event, and run a test before enabling it. Only the current author can call `POST /api/user-automations/<id>/test` with `{commandId,recordId,event}`. Existing authoring is installation-owner-only (AUTO-USER-009's creator duty remains).

The conservative default is dry: update steps show the exact field before/after without writing; notifications are previewed without creating anyone's notification; webhook and Slack steps prepare their actual payload and destination without transport. Email is the explicit builder-only exception: it uses the installation sender and the builder's server-resolved own address, showing the original operator recipient under `wouldHaveUsed`. Each step returns its input, output and state. Trigger mismatch skips all steps and sends nothing. Current author, row, field, export, recipient and definition/version authority is checked before any effect.

To make a live test, first obtain a dry preview, then send the same endpoint `{commandId,recordId,event,live:{previewId,effects}}`. `effects` must exactly name every previewed notification or external step's position, kind and destination. A changed definition, record or destination refuses the confirmation. The editor requires a separate checkbox for each named effect. Live tests run the ordinary action implementation under current authority, with ordinary bounds and destination checks.

Tests are durably claimed before any send. Repeating the same command never sends again. Provider uncertainty is shown as Unknown and has no automatic resend or recovery path; a restored test cannot dispatch. The run history labels Test and Live test, retains definition version, step and error states, and uses a separate test table excluded from AUTO-006's ordinary execution counts and success rate.

Custody: `record_automation_tests` stores projected step inputs/results, the author and chosen record, versions and a confirmation digest. Receiver URLs and signing secrets are absent from durable test results; a signed receiver preview is returned only to the currently authorized author. Generic installation export/restore carries test history with no dispatch path. Member identity erasure registers the authored test rows for scrubbing. Complete archive/restore and erasure acceptance for these rows remains unproven.

Evidence: `tests/user-automations.mjs` — `[AUTO-USER-005] real admitted record triggers run notify/email/update once, retain history, and stop disabled or revoked work`, extended by `tests/helpers/automation-test-journey.mjs`; browser panel: `tests/ui-user-automations.mjs` and `tests/helpers/automation-test-browser.mjs`. Desktop and phone checks pass without horizontal overflow or serious/critical axe findings; `test-panel-*.png` shows both the chosen record and the completed step output.
