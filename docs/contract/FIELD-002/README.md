# Field conversion and schema Trash (partial)

Conversion runs through the existing schema preview and `release.adopt`, with current schema, records, dependents and authority fenced again at adoption. Existing record identities, timestamps, versions and history remain. A creator's lossy conversion, field deletion or table deletion waits for the base owner's review; editors cannot prepare schemas. Recovery exports retain original typed values by `_record_id`.

The explicit mappings are text to/from select (exact human labels), select to one linked record (one exact unchanged text-primary match), number to USD currency (exact cents without rounding), USD currency to number, text to/from date (ISO or month/day/year), and text to/from number. Unmatched/ambiguous labels, invalid dates/numbers, foreign currency and inexact cents appear as individual lost-value examples. Optional losses become empty only after review. A required loss refuses adoption. Attachment/store-reference and calculated-field conversions, undefined pairs, option changes and relationship retargeting are explicitly refused; no file reference is converted or made portable.

The preview enumerates real formula/rollup, relation/picker/rule, saved view filter/sort/group/layout/visible-field, form and conditional-field, automation and API credential policy-scope references. Unresolved calculated, automation and type-sensitive dependencies refuse adoption. A deleted field is pruned from current saved views/forms, and restoration returns the original unedited references. Concurrent dependent changes invalidate the preview. Interface dependents cannot be checked: IFACE-001 has no interface object. ct approved moving that duty into IFACE-001 on 23 October; it remains unproven there.

Fields and isolated tables share `record_trash`, its 30-day clock and the Settings Trash door. Field markers reference the existing authorized release snapshot, rather than another value store. Deleted tables retain their canonical schema/data pointer behind the Trash marker; normal descriptor loading hides them. Restoration requires current destructive authority. A recreated name or identity, changed dependent metadata, absent link target or missing recovery snapshot refuses restoration without overwrite. Table deletion with surviving incoming/outgoing links, views, forms, automations or calculations is refused until cascade restoration can be proved.

Expiry disables restoration and exposes `blocked_recovery_custody`; complete disposal of physical revisions and recovery copies is not implemented. Person erasure continues to refuse unresolved historical/recovery identity copies rather than claiming they were erased. No complete schema-Trash erasure or purge is claimed.

Evidence: `tests/records-manual-release.mjs` invokes `tests/helpers/field-conversion-journey.mjs` (one data-driven conversion matrix) and `tests/helpers/field-trash-journey.mjs` (field/table deletion, recovery, restoration, collisions, metadata and history). `tests/ui-records-builder.mjs` invokes `tests/helpers/field-browser.mjs` for the existing field controls, refusal, lossy creator preview, owner review, adoption/recovery and Trash at 1440 and 390. The changed components use text-labelled controls; their mobile host uses the existing 300 ms hover/immediate keyboard-focus tooltips. No real provider call or consent was used.
